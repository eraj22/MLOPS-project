================================================================================
STEP 0: PREREQUISITES (run once)
================================================================================

1) Update system and install basic tools:

    sudo apt update && sudo apt upgrade -y
    sudo apt install -y python3 python3-venv python3-pip git curl unzip

2) Install Docker (needed for building/running containers, and for the
   observability stack with docker-compose):

    sudo apt install -y ca-certificates curl gnupg
    sudo install -m 0755 -d /etc/apt/keyrings
    curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
    echo \
      "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
      $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
      sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
    sudo apt update
    sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

3) Allow running docker without sudo (log out/in or restart WSL after this):

    sudo usermod -aG docker $USER
    newgrp docker

4) Verify installs:

    python3 --version
    docker --version
    docker compose version

================================================================================
STEP 3: CONFIGURE ENVIRONMENT VARIABLES
================================================================================

1) Copy the example env file:

    cp .env.example .env

2) Edit it:

    nano .env

   At minimum set:
     SLACK_WEBHOOK_URL=<your real Slack webhook URL>   (see Step 9 below)

   Leave RECORDS_API_URL as-is (it is the only allowed endpoint):
     RECORDS_API_URL=http://149.40.228.124:6500/records

3) Load the env vars into your current shell session:

    export $(grep -v '^#' .env | xargs)


================================================================================
STEP 4: RUN DATA INGESTION (Part 1)
================================================================================

Run once (single fetch + schema/drift check):

    python ingestion/ingestion.py --once

Check results:

    cat data/records.csv | head
    cat data/last_schema.json

If the API returns 503, you'll see it logged and the datalake_unavailable
counter increments + a Slack alert fires (if SLACK_WEBHOOK_URL is set).

(Optional) Run continuously in the background, polling every
POLL_INTERVAL_SECONDS:

    python ingestion/ingestion.py &


================================================================================
STEP 5: TRAIN THE MODEL (Part 2)
================================================================================

    python model/train.py

This creates:
    model/model_v1.pkl
    model/current_version.json

If data/records.csv doesn't have enough rows or no "label" column yet, it
automatically falls back to a synthetic dataset so the pipeline still runs.

NOTE: If the live API's records use a different target column name than
"label", set TARGET_COLUMN in .env before training, e.g.:
    echo "TARGET_COLUMN=your_target_column_name" >> .env
    export TARGET_COLUMN=your_target_column_name


================================================================================
STEP 6: RUN THE INFERENCE API LOCALLY (Part 3 - local check before AWS)
================================================================================

1) Start the server:

    uvicorn serving.app:app --host 0.0.0.0 --port 8000 &

2) Test endpoints:

    curl localhost:8000/health

    curl -X POST localhost:8000/predict \
      -H "Content-Type: application/json" \
      -d '{"features": {"feature_1": 0.5, "feature_2": 5.0, "feature_3": 3.0}}'

    curl localhost:8000/metrics | head -30

3) Stop it when done:

    pkill -f uvicorn

    python model/retrain_trigger.py            # checks conditions, retrains if needed
    python model/retrain_trigger.py --force     # force retrain regardless of conditions

================================================================================
STEP 13: LAUNCH AWS EC2 INSTANCE (Part 3)
================================================================================

1) AWS Console -> EC2 -> Launch Instance
2) Name: mlops-inference
3) AMI: Ubuntu Server 22.04 LTS
4) Instance type: t2.micro (free tier)
5) Key pair: create new -> name it "mlops-key" -> download "mlops-key.pem"
   (move it into ~/mlops-project/ or note its path)
6) Security Group - add inbound rules:
     SSH    TCP  22    Source: My IP
     HTTP   TCP  80    Source: 0.0.0.0/0
     Custom TCP 8000   Source: 0.0.0.0/0
     Custom TCP 9090   Source: 0.0.0.0/0   (Prometheus, if hosted here too)
     Custom TCP 3000   Source: 0.0.0.0/0   (Grafana, if hosted here too)
     Custom TCP 9093   Source: 0.0.0.0/0   (Alertmanager, if hosted here too)
7) Launch instance
8) Copy the "Public IPv4 address" -> this is your EC2_HOST

9) Fix key permissions (WSL):

    chmod 400 ~/mlops-project/mlops-key.pem


================================================================================
STEP 14: INSTALL DOCKER ON THE EC2 INSTANCE
================================================================================

    ssh -i ~/mlops-project/mlops-key.pem ubuntu@<EC2_PUBLIC_IP>

Once connected, run on the EC2 instance:

    sudo apt update
    sudo apt install -y docker.io
    sudo usermod -aG docker ubuntu
    exit

Reconnect so the docker group applies:

    ssh -i ~/mlops-project/mlops-key.pem ubuntu@<EC2_PUBLIC_IP>
    docker --version
    exit


================================================================================
STEP 15: BUILD, PUSH, AND DEPLOY TO EC2 (Part 3 deploy script)
================================================================================

Back on your WSL machine, from ~/mlops-project:

1) Export required variables:

    export DOCKER_USERNAME=eraj22
    export DOCKER_PASSWORD=<your_dockerhub_access_token>
    export DOCKER_IMAGE_NAME=eraj22/mlops-inference
    export IMAGE_TAG=latest

2) Build and push the image to Docker Hub:

    chmod +x deploy/deploy.sh
    ./deploy/deploy.sh build-and-push

3) Now configure remote-deploy variables:

    export EC2_HOST=<EC2_PUBLIC_IP>
    export EC2_USER=ubuntu
    export EC2_SSH_KEY_PATH=~/mlops-project/mlops-key.pem
    export SLACK_WEBHOOK_URL=<your_slack_webhook_url>

4) Deploy to EC2 (pulls image, runs container):

    ./deploy/deploy.sh remote-deploy

   (Or do both build+push and deploy in one go: ./deploy/deploy.sh all)

================================================================================
STEP 20: TRIGGER AND DEMO ALL 7 SLACK ALERTS (Part 6)
================================================================================

With the EC2 service running and SLACK_WEBHOOK_URL configured, run each of
these one at a time (wait ~30-60 seconds between each for Prometheus to
scrape + Alertmanager to fire):

    BASE=http://<EC2_PUBLIC_IP>:8000

    curl -X POST $BASE/debug/trigger/datalake          # Alert 1: DataLakeUnavailable
    curl -X POST $BASE/debug/trigger/feature_added     # Alert 2: FeatureAdded
    curl -X POST $BASE/debug/trigger/feature_removed   # Alert 3: FeatureRemoved
    curl -X POST $BASE/debug/trigger/drift             # Alerts 4 & 5: Drift
    curl -X POST $BASE/debug/trigger/latency           # Alert 6: HighResponseLatency
    curl -X POST $BASE/debug/trigger/low_accuracy      # Alert 7: LowModelAccuracy

After each one, check #mlops-alerts in Slack and screenshot the message
into screenshots/.

Reset state afterward:

    curl -X POST $BASE/debug/trigger/clear_drift
    curl -X POST $BASE/debug/trigger/restore_accuracy
